# Astralow-for-editable-ppt

忠实保留源图文字、布局与视觉关系，交付可编辑 PPTX 和实际渲染预览。此 Skill 不切换模型；Astra low 由用户或调用方选择。尚未验证跨页面类型的 token 节省比例。

## 使用

先看源图，再决定重建方法。文字、数字和适合原生表达的主要结构用可编辑对象；复杂视觉可以合理保留局部裁图，说明哪些部分内部不可编辑。不要把整页图片包装成“可编辑重建”。用户要求图表数据、表格单元格或图标路径可编辑时，按该要求选择对象类型；不能从图片可靠恢复的信息应明确说明。

使用 [工具接口](references/tools.md) 中的 `Deck`，把重复的绘图、保存、渲染和报告工作交给脚本。只需读接口，不必预读脚本源码。模型独立决定文字、坐标、字体、颜色和裁图范围；接口不足时使用 `deck.slide` / `deck.presentation` 或其他合适工具。不要为满足接口而简化用户要求。

`finish()` 返回本轮预览路径与状态；在同一轮工具执行中接着展示预览，省去单独查目录。检查最终整页，对疑点再局部放大。修订后查看新预览；按实际问题决定是否继续修订，不设固定轮数。

优先复核文字、数字、遗漏、重叠、文字与容器边界、裁图底色以及明显样式差异。宽度估算和对象数量仅辅助定位，不证明还原质量。对密集文字或识别疑点，按 [质量检查](references/quality.md) 使用局部查看或已有 OCR；不用默认生成长篇逐对象报告。

交付前可用随附的 `verify-edit.ps1` 在副本上做改字、保存、重开验证；接口和适用范围见质量检查。明确区分已验证、未验证和局部图片。最终回复提供 PPTX、预览及必要限制，避免重复过程日志。

## 范围

- 基础构建工具一次处理一张源图、一页 PPT；多页按页处理，保持顺序。合并时保留原生对象，并检查最终合并文件。工具未提供通用多页合并器。
- 新建基础对象使用明确样式以避免意外主题效果；不统一删除源图需要的阴影、渐变或模板样式。
- Python 依赖见 `requirements.txt`。实际 Office 渲染与编辑验证需要 Windows 桌面 PowerPoint；不可用时保留 PPTX 并明确未验证，不能把其他渲染器结果称为 Office 验证。
