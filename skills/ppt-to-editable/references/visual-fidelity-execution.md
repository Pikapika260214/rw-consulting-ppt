# Visual Fidelity Execution

Use this reference in ppt-to-editable v3 preview only when a worker needs fallback detail beyond `WORKER_COMPACT_PROTOCOL.md`.

This is an execution contract, not only a final QA checklist. Apply it while building the slide.

## Contract-First Execution

For v3 preview multi-page runs, each slide job includes compact generated context
files from the deck controller:

- `WORKER_COMPACT_PROTOCOL.md`: the default short execution protocol.
- `page_conversion_contract.json`: default execution policy for text, native
  shapes, font, effects, fallback decisions, and source dimensions.
- `crop_manifest_contract.json`: the required crop evidence format and
  protected-anchor rules.
- `routing_decision_table`: the controller's default region-level route table.
- `reference_loading_policy`: the minimum context to read and the historical
  materials to avoid during a clean conversion.

Apply these before creating `source_reconstruction_plan.json`. They are meant to
control the conversion step itself, not only the final QA report.

If a region contains complex artwork, shaded cards, detailed icons, product
images, source-specific arrows, route lines, gradient arrow bars, matrix
backgrounds, or dense composite modules, start from a source crop or textless
crop plus editable text. Do not spend the attempt budget forcing native shapes
when the source crop preserves fidelity better.

When crops are used, write `crop_manifest.json` before packaging. It should make
the crop decision auditable: region id, bbox/source image, chosen strategy,
protected anchors, text removal scope, and reason. If no crop is needed, write an
empty manifest with `reason=no_source_crops_required`.

## Required Reading And Reporting

Do not read this reference by default. Read it only when blocked, when a
visual fidelity QA gate fails, or when the compact protocol is ambiguous.

Default compact `references_read` should contain the ids generated by
`slide_job_manifest.json`, normally:

```json
{
  "references_read": [
    "worker_compact_protocol",
    "slide_job_manifest",
    "page_conversion_contract",
    "crop_manifest_contract"
  ],
  "fallback_references_read": [
    "visual_fidelity_execution"
  ]
}
```

Only include `visual_fidelity_execution` in `fallback_references_read` if this
long reference was actually read. The controller treats missing compact required
reading as `failed-retryable`; it does not require long fallback references when
the compact protocol was sufficient.

## PowerPoint Render Loop

There are two different PNGs:

- source PNG: extracted from the original image-only PPTX and used as the visual target;
- rendered PNG: exported from the generated editable PPTX and used to see what PowerPoint will actually show.

For each per-slide output when PowerPoint or LibreOffice is available:

1. Build the editable one-slide PPTX.
2. Export that PPTX to a rendered PNG through PowerPoint or LibreOffice.
3. Compare the rendered PNG against the source PNG.
4. Fix visible execution defects before returning the slide.

Fix these during conversion, not only during final review:

- text overlap;
- text overflow outside the intended card, row, callout, or panel;
- font fallback to theme fonts or SimSun;
- one-character orphan wraps;
- unwanted shadows, glow, bevel, soft edge, or theme effects;
- row, matrix, connector, card, or callout drift;
- source text residue inside textless crops.

Do not mark a slide `passed` without rendered PNG review when PowerPoint/LibreOffice is available. If rendering is unavailable, record the limitation and use `accepted-with-limitations` at most.

Rendered PNG review is a conversion loop, not a screenshot attachment. If rendered review finds text overflow, text overlap, font fallback, unwanted effects, major layout drift, or obvious text-size drift, fix the slide before returning it. If the worker cannot fix it within the allowed attempt, mark the slide `failed-retryable`.

## Font Contract

Default every generated text box and text run to Microsoft YaHei.

When writing with python-pptx or direct OOXML, explicitly set:

- Latin font: `Microsoft YaHei`
- East Asian font: `Microsoft YaHei`
- complex script font: `Microsoft YaHei`

Do not rely on PowerPoint theme fallback. A slide that visually falls back to SimSun or another serif Chinese font must be revised.

Record in `qa_summary.json`:

```json
{
  "font_policy_applied": "microsoft-yahei-all-runs"
}
```

## Font Size Consistency

Do not solve fitting problems by shrinking readable body, callout, or panel text into tiny outliers.

During conversion:

1. Preserve the source slide's relative type hierarchy: title, subtitle, section labels, body text, footnotes, and caveats should remain in the same visual order.
2. When text does not fit, first adjust the text box, region crop boundary, line breaks, or semantic grouping.
3. Reduce font size only as a small correction. Do not make a main body/callout line visibly smaller than the same role in the source slide.
4. If a small source/caveat text is genuinely tiny in the original, keep it small but record that as source-matched, not as a fitting workaround.

Record in `qa_summary.json`:

```json
{
  "font_size_consistency_review": {
    "status": "reviewed",
    "issues": []
  }
}
```

If visible body text becomes a tiny outlier, use `failed-retryable` with a reason such as `tiny-font-outlier` or `font-size-hierarchy-drift`.

## Native Shape Effects

Generated native shapes, connectors, text boxes, and picture crops default to no effects.

Clear or avoid:

- shadow;
- glow;
- bevel;
- reflection;
- soft edge;
- inherited theme `effectRef`;
- OOXML `effectLst` or `effectDag`.

Only preserve an effect when the source clearly uses it and removing it would make the slide less faithful. Decorative PowerPoint default shadows are not allowed.

Record in `qa_summary.json`:

```json
{
  "effects_cleared": true
}
```

## Region Crop Planning

Do not use one full-slide textless background crop as the default answer for complex pages.

For complex structured slides, first divide the page into semantic regions. Typical regions:

- title/header;
- left module or row-label column;
- central matrix, process, timeline, or proof object;
- right decision/control panel;
- footer, caveat, source, or takeaway.

Use native objects for simple stable elements. Use local textless crops for visual regions where native redraw would drift. Keep all meaningful readable text editable unless the user explicitly accepts otherwise.

For complex visual modules, use crop-first judgment during execution. Product photos, detailed icons, curved paths, gradient arrows, textured modules, layered card stacks, and source-specific process visuals should be source-derived crops or textless crops unless a native redraw clearly matches the original.

In v3.1, high-risk native redraw is not accepted just because an `override_reason` exists. If a high-risk region is still implemented as `native_redraw`, `native_lines`, `native_shapes`, or `native_reconstruction`, stop and change that region to a bounded source crop or textless crop plus editable text before packaging.

Record in `qa_summary.json`:

```json
{
  "complex_visual_strategy_review": {
    "status": "reviewed",
    "complex_region_count": 0,
    "crop_first_region_count": 0,
    "unresolved_native_redraw_drift": false,
    "issues": []
  }
}
```

If a complex region was redrawn natively and became visibly worse, use `failed-retryable` with `native-redraw-complex-artwork` or `native-redraw-worsened-fidelity`.

For a complex structured slide, use at least three semantic regions unless the slide truly has fewer major regions. A typical slide should have 3 to 5 regions, and more is acceptable when it improves editability and selection.

Whole-slide textless crop is allowed only as an explicit fallback with a recorded limitation:

```json
{
  "limitation": "whole_slide_textless_crop_explicitly_accepted"
}
```

For mixed reconstruction, a whole-slide/background picture cannot satisfy a semantic 3-5 region plan. Each crop-first region should point to a bounded source/textless crop, clean badge composite, or native object evidence. If multiple strategy regions all cite the same whole-slide/background picture, the attempt must be `failed-retryable` or `image-fallback`, not `passed` or `accepted-with-limitations`.

For quality forward tests, OCR unavailable or manual layout guessing is not an acceptable region-planning substitute. Without OCR geometry, the worker must either use a validated alternative geometry source or mark the page `failed-retryable`.

Record the plan in `qa_summary.json`:

```json
{
  "region_crop_plan": [
    {
      "id": "central_matrix",
      "strategy": "textless_crop_plus_editable_text",
      "source_bbox_px": [80, 190, 1510, 760],
      "reason": "native redraw would change row spacing and background fidelity"
    }
  ]
}
```

## Mixed Reconstruction Policy

Do not maximize native shapes if that makes the slide look worse.

Complex shapes must not be forced into native PowerPoint reconstruction. For bespoke process arrows, shaded cards, icon clusters, source-specific modules, dense callouts, or detailed visual objects, use a tight source crop or textless crop plus editable text when native redraw would look template-like, distorted, misaligned, or less faithful than the source.

Use this decision rule:

- stable flat rectangles, dividers, simple circles, and true dashed lines: native;
- detailed icons, shaded badges, gradient bars, complex matrix backgrounds, source-specific callouts, or arrow-ended bands: local source-derived crop;
- all meaningful readable text: editable native text placed above native shapes or textless crops.

If native redraw causes visible drift, switch that region to a local textless crop plus editable text.

## Non-Text Anchor Preservation

Textless crop cleanup must not erase the slide structure. Preserve arrows, arrowheads, route lines, connectors, step markers, card edges, cut corners, dividers, and icons. If text removal damages one of these anchors, redo the crop, split the crop into smaller regions, or keep the affected anchor as a source-derived element before returning success.

Record in `qa_summary.json`:

```json
{
  "non_text_anchor_preservation_review": {
    "status": "reviewed",
    "protected_anchor_count": 0,
    "crop_protected_anchor_count": 0,
    "missing_required_anchors": false,
    "issues": []
  }
}
```

If a required anchor is missing, broken, clipped, or erased, use `failed-retryable` with `missing-non-text-anchor`, `missing-arrowhead`, `broken-route-line`, or `cropped-icon`.

## Text Background Policy

Editable text boxes should be transparent unless the source slide already has a visible card, bar, pill, or label background at that location.

Do not add pale rectangles, generic backing fills, or invented text background blocks just to hide old source text or improve readability. If source text remains under editable text, repair the local visual region as a textless crop, then overlay the editable text.

Record in `qa_summary.json`:

```json
{
  "text_background_policy": {
    "status": "reviewed",
    "invented_text_backgrounds_added": false,
    "issues": []
  }
}
```

If invented backing fills are present, use `failed-retryable` with `invented-text-background`.

## Required Per-Slide QA Fields

Delegated per-slide outputs must include these fields in `qa_summary.json`:

```json
{
  "status": "passed | accepted-with-limitations | failed-retryable | image-fallback",
  "mode": "clean-background | reconstruction | mixed-reconstruction",
  "references_read": [],
  "font_policy_applied": "",
  "font_size_consistency_review": {},
  "effects_cleared": false,
  "rendered_png_reviewed": false,
  "region_crop_plan": [],
  "crop_manifest": {},
  "complex_visual_strategy_review": {},
  "text_background_policy": {},
  "non_text_anchor_preservation_review": {},
  "editable_text_count": 0,
  "native_shapes_count": 0,
  "source_crop_count": 0,
  "visual_qa": {},
  "failure_reason": "",
  "limitations": [],
  "recommended_next_round_change": "",
  "worker_identity": {},
  "ocr_runtime_status": "passed-text-usable",
  "single_page_engine_used": "ppt-to-editable-v3-1-preview",
  "single_page_engine_scripts_used": []
}
```

`accepted-with-limitations` is only for minor visual differences such as non-editable icons or slight texture mismatch. Text overlap, text overflow, font fallback, unwanted shape effects, OCR unavailable, manual layout guessing, obvious text-size drift, and major layout drift are `failed-retryable`.

The deck controller rejects successful statuses when:

- no real per-slide worker identity is reported;
- `progress.json` does not include all required milestones;
- OCR was unavailable at dispatch;
- blocking limitations are present;
- rendered PNG review is missing;
- the semantic region plan is missing or too shallow for a complex structured slide;
- `region_crop_plan` contains strings, `not-reported` placeholders, missing `source_bbox_px`, or missing `reason`;
- `source_reconstruction_plan.json` or `visual_strategy_report.json` still uses native redraw for a high-risk region;
- a high-risk plan has zero source crops and many native shapes/lines;
- multiple semantic regions cite the same whole-slide/background picture instead of real bounded crop/native evidence;
- `single_page_engine_used` does not prove use of `ppt-to-editable-v3-1-preview`;
- reconstruction or mixed reconstruction does not report the integrated deterministic packager / QA script path.
- `font_size_consistency_review` is missing or reports tiny-font drift.
- `complex_visual_strategy_review` is missing or reports unresolved native redraw drift for complex artwork.
- `text_background_policy` is missing or reports invented text backing fills.
- `non_text_anchor_preservation_review` is missing or reports missing, broken, clipped, or erased non-text anchors.
